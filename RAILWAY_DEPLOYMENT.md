# Railway Deployment Guide

This guide walks you through deploying the BBA Client Platform to Railway with PostgreSQL and AI capabilities.

---

## Prerequisites

1. **Railway Account**: Sign up at [railway.app](https://railway.app)
2. **GitHub Repository**: Your code must be pushed to GitHub
3. **OpenRouter API Key**: Obtain from [openrouter.ai](https://openrouter.ai)

---

## Part 1: Database Migration (SQLite → PostgreSQL)

### What Changed

✅ **Prisma Schema** (`packages/db/prisma/schema.prisma`)
- Changed `provider = "sqlite"` to `provider = "postgresql"`

✅ **Root Build Scripts** (`package.json`)
- Added `prisma generate` step before Next.js build
- Added `start` script for production

✅ **Environment Variables** (`.env.example`)
- Added `OPENROUTER_API_KEY`
- Added `NEXT_PUBLIC_AI_ENABLED`

## Part 2: Railway Setup

### Step 1: Create New Project

1. Go to [railway.app/new](https://railway.app/new)
2. Click **"Deploy from GitHub repo"**
3. Select `NobleSavageGlobal/bba-client-platform`

### Step 2: Add PostgreSQL Database

1. In your Railway project, click **"New"** → **"Database"** → **"Add PostgreSQL"**
2. Railway automatically creates a `DATABASE_URL` variable
3. Link the database to your web service

### Step 3: Configure Environment Variables

Click on your web service, go to **"Variables"** tab, and add:

| Variable | Value/Notes |
|----------|-------------|
| `DATABASE_URL` | ✅ Auto-generated by Railway PostgreSQL |
| `NEXTAUTH_SECRET` | Generate with: `openssl rand -base64 32` |
| `NEXTAUTH_URL` | Your Railway URL (e.g., `https://web-production-xxxx.up.railway.app`) |
| `OPENROUTER_API_KEY` | Your OpenRouter API key (get from [openrouter.ai/keys](https://openrouter.ai/keys)) |
| `NEXT_PUBLIC_AI_ENABLED` | `true` |
| `SMTP_HOST` | Your SMTP server (e.g., `smtp.gmail.com`) |
| `SMTP_PORT` | `587` |
| `SMTP_USER` | Your email address |
| `SMTP_PASS` | Your email password or app-specific password |
| `NOTION_TOKEN` | (Optional) Your Notion integration token |
| `GOOGLE_CLIENT_ID` | (Optional) For Google Drive integration |
| `GOOGLE_CLIENT_SECRET` | (Optional) For Google Drive integration |
| `GOOGLE_DRIVE_FOLDER_ID` | (Optional) Target folder ID |

### Step 4: Initialize Database Schema

After your first deployment:

1. Click on your web service in Railway
2. Go to **"Settings"** → **"Deploy"**
3. Add a **"Build Command"** override (one-time):
   ```bash
   prisma generate --schema=packages/db/prisma/schema.prisma && npx prisma db push --schema=packages/db/prisma/schema.prisma && npm run build --workspace=apps/web
   ```
4. After successful deployment, remove the `npx prisma db push` part from the build command
5. Final build command should be:
   ```bash
   prisma generate --schema=packages/db/prisma/schema.prisma && npm run build --workspace=apps/web
   ```

**Alternative:** Use Railway's CLI to run migrations:
```bash
railway run npx prisma db push --schema=packages/db/prisma/schema.prisma
```

## Part 3: AI Integration

### Features Enabled

✅ **AI-Powered Document Processing**
- Automatically extracts tax data from W2s, 1099s, bank statements
- Uses Minimax M2.5 for structured JSON extraction
- Falls back to rule-based parsing if AI is disabled

✅ **Chat Assistant API** (`/api/chat`)
- Streaming chat completions for client Q&A
- Context-aware tax and business advisory
- Protected by authentication

### How It Works

1. **Document Upload** → User uploads tax document
2. **AI Classification** → Minimax M2.5 identifies document type
3. **AI Extraction** → Minimax M2.5 extracts structured data (income, taxes, period)
4. **Storage** → Data saved to PostgreSQL with high precision
5. **Checklist Update** → Automatically marks off completed requirements

### Cost Considerations

| Model | Use Case | Cost per 1M tokens |
|-------|----------|-------------------|
| Minimax M2.5 | Document extraction & chat | $0.55 input / $2.80 output |

**Estimated monthly cost for 100 clients:**
- ~1000 documents/month × $0.002/doc = **$2/month**
- ~5000 chat messages/month × $0.004/msg = **$20/month**
- **Total: ~$22/month** (vs $150/month with OpenAI)

**Savings: ~85% cheaper than GPT-4!**

## Part 4: Testing Locally Before Railway

### Setup Local PostgreSQL (Optional)

If you want to test PostgreSQL locally before deploying:

```bash
# Install PostgreSQL (macOS)
brew install postgresql@15
brew services start postgresql@15

# Create database
createdb bba_dev

# Update .env
DATABASE_URL="postgresql://localhost:5432/bba_dev?schema=public"
OPENROUTER_API_KEY="sk-your-key-here"
NEXT_PUBLIC_AI_ENABLED="true"

# Push schema
npx prisma db push --schema=packages/db/prisma/schema.prisma

# Start dev server
npm run dev
```

### Test AI Processing

1. Log in as admin
2. Upload a sample W2 or 1099 PDF
3. Click "Process" button
4. Check browser console for extraction results

## Troubleshooting

### Build Fails: "Prisma Client not generated"
**Solution**: Ensure build command includes `prisma generate`:
```bash
prisma generate --schema=packages/db/prisma/schema.prisma && npm run build --workspace=apps/web
```

### Database Connection Error
**Solution**: Verify `DATABASE_URL` format:
```
postgresql://user:password@host:port/database?schema=public
```

### AI Processing Fails
**Solution**: Check environment variables:
- `OPENROUTER_API_KEY` is set correctly
- Key has sufficient credits
- `NEXT_PUBLIC_AI_ENABLED="true"`

### Chat Returns 503 Error
**Solution**: Ensure `NEXT_PUBLIC_AI_ENABLED` is set to `"true"` (string, not boolean)
